# 丸丸资产 · 生成记录

这份文件回答一个问题：`docs/design/` 下的三张方向稿、以及 `src/xiaocc/characters/xiaocc/assets/`
下的 7 个状态矢量稿，到底是怎么来的。内容是生成规格、逐文件来源、生成工具与人工校对点的留档，
供公开仓库里「美术资源为原创、含 AI 辅助生成」这句声明对照核查。

形象定位与设计意图见 `丸丸-资产说明.md`，对外许可声明见仓库根目录 `ASSET_LICENSE.md`。

## 1. 生成工具与流程

- 工具：**Codex CLI**（`codex exec`），逐文件生成。不是图像模型出图，产物是可直接读的 SVG 文本。
- 流程：项目先定形象方向（`README.md` 里的 A / B / C 三选一）→ 写出书面几何规格（第 3 节）
  → 每个文件按「几何规格 + 该状态的表情与 accent」生成 → 人工校对坐标与画布边界 → 入库。
- 产物形态：`rect` / `path` / `circle` / `linearGradient` 组成的纯矢量，无位图、
  无外部字体依赖、透明背景。交付的就是生成出来的文件，只经过人工校对与手改坐标。
- 检视工具：`scripts/art_montage.py` 把 7 档拼成一张对照图（原尺寸 + 60px + 32px 三档），
  用来同时判断「7 档是不是一眼能区分」和「缩到 60px 是不是还认得出来」。
  它只做渲染检视，不参与生成，也不是生成流程里的中间格式。

## 2. 文件清单与生成来源

7 个状态资产，路径统一为 `src/xiaocc/characters/<角色>/assets/<状态>.svg`，
内置角色目录是 `xiaocc`：

| 文件 | 状态 | 生成输入 | accent | 面罩表情 | 姿态或附加元素 |
| --- | --- | --- | --- | --- | --- |
| `assets/idle.svg` | idle | 第 3 节规格 + idle | `#6FD3E8` | 一道上扬的嘴弧 | 两手自然下垂 |
| `assets/thinking.svg` | thinking | 第 3 节规格 + thinking | `#8FA7FF` | 三个点 | 一只手抬到面罩旁 |
| `assets/working.svg` | working | 第 3 节规格 + working | `#FFC24B` | `>` `>` 尖括号 | 举手拿扳手 + 小火花 |
| `assets/waiting.svg` | waiting | 第 3 节规格 + waiting | `#FF8A5B` | 大感叹号 | 一只手向外招 |
| `assets/done.svg` | done | 第 3 节规格 + done | `#5BD08A` | 两道 `^` 笑眼 | 两侧小星星 |
| `assets/error.svg` | error | 第 3 节规格 + error | `#F2665E` | 两个 `×` | 头顶火花线，整组倾斜 -5° |
| `assets/offline.svg` | offline | 第 3 节规格 + offline | `#9AA1B1` | 一道横线（闭眼） | 整身灰调、灯珠熄灭 |

「第 3 节规格」对每个文件是同一份，差异只有三处：accent 色、面罩表情、附加元素。
也就是说 7 个文件不是 7 套独立画法，而是同一份几何规格 + 7 组状态参数的产物，
这也是新增状态不必重画整张图的原因。

方向稿：`docs/design/方向A-星屑小灵.svg`、`方向B-胶囊机甲丸丸.svg`、`方向C-围巾小兽雪球.svg`
是同一生成方式的概念稿（三选一用的判断稿），画布 `820×380`，每张含三个状态
（待机 / 干活 / 出错），不是最终美术。选定方向 B 之后，正式稿按第 3 节规格重排进 `132×140`。

## 3. 共用几何规格

这份规格就是生成时逐文件使用的书面输入（等价于提示词），7 个状态资产与方向稿的正式稿部分共用：

| 要素 | 规格 |
| --- | --- |
| 画布 | `viewBox="0 0 132 140"`，透明背景（不铺底色 rect） |
| 组变换 | 全部可视元素包在 `translate(66 80) scale(0.94)` 的 `<g>` 内 |
| 渐变 `shell` | `#FFFFFF` → `#EEF1F7` → `#D3DAE8`（身体金属感） |
| 渐变 `visor` | `#2A3242` → `#171C26`（面罩深色） |
| 渐变 `glow` | accent `0.5` → accent `0`（灯环 / 灯珠外发光） |
| 身体 | `rect x="-38" y="-44" width="76" height="88" rx="34"` |
| 面罩 | `rect x="-28" y="-26" width="56" height="34" rx="16"` |
| 灯环 | `rect x="-22" y="22" width="44" height="7" rx="3.5"` |
| 天线 | `path d="M0 -44 v -12"` + 灯珠 `circle cy="-59" r="5.5"` |
| 表情线宽 | 3.6 ~ 4.4，保证缩到 60px 仍看得清 |
| 边界 | 所有元素必须落在画布内（含 `error` 倾斜 -5° 之后的包围盒） |

渐变 id 固定为 `shell` / `visor` / `glow`，跨文件替换 accent 时统一处理这三处。

## 4. 人工校对点

生成不是终点，每个文件都人工过了一遍坐标与画布边界。已知在这一步被改掉的具体两处：

- `waiting` 的手臂：生成稿的手臂位置不对，人工调整到「向外招」的姿态；
- `idle` 的嘴弧：弧向反了，人工改成上扬。

其余文件在校对中确认了元素落在画布内、灯环与天线对齐、以及 `error` 整组倾斜 -5° 后的
包围盒没有出界。新增状态照第 3 节规格与本节做法复现即可。
