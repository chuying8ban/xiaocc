# 额度（quota）数据来源与口径

面板顶上那几行余额从哪来、为什么有的家只能写「无自动接口」，依据都在这页。
面板上的 `hint`/`detail` 只写**结论 + 一个动作**（宽度只有一行的预算），
完整的取数依据、探测过程和口径规矩放这里。

## 一家一家说

| 服务 | 取数路径 | 实测结论 |
| --- | --- | --- |
| **DeepSeek** | `GET https://api.deepseek.com/user/balance`（官方余额接口，key 走 `DEEPSEEK_API_KEY`） | 唯一一家有真余额接口的：可用余额、其中赠送、其中充值三项都是真数 |
| **千问云 Token Plan** | 官方 CLI `qianwen`（本机未安装时无法取数） | 装好后跑一次 `qianwen auth login`，浏览器批准一次即可；之后由 CLI 输出额度 |
| **百炼 DashScope** | 无 | **per-key 无余额接口**：`/usage`、`/quota`、`/user/balance` 等 7 条候选路径实测全部 404。账户级余额要 BSS AK/SK 签名才能查，而且**账户总额度 ≠ 百炼套餐余量**（两个口径，取到也不是面板想显示的那个数） |
| **Nous Portal** | 无 | 没有公开额度接口；本机 `credential_pool.nous` 为空 ⇒ 需登录后在控制台看 Credits |

所以面板上「1 家有接口 / 4 家」这个比例是**事实**，不是没做：其余几家官方不提供机器可读的额度。

## 口径（三条，都是真机上量出来才定的）

1. **取不到就写「未知」，绝不补 0** —— 把「不知道」画成 `¥0.00`，和把额度画错一样是假数。
2. **陈旧要区分开**：上次拿到了、这次没刷新 ⇒ `stale`（页面上写「数据陈旧 · N 分钟未更新」），
   不是「未知」，也不是新的数。
3. **「未计价的行」和「金额未知的模型」是两件事**：成本 = 全部行 `estimated_cost_usd` 求和；
   「未计价」只算既没有金额、状态也不可信的行。只读默认库会漏掉约 41%，所以「本机账本」一节
   分「默认 profile」与「全部 profile（N 个库）」两个口径，库里数量由磁盘上的
   `profiles/*/state.db` 决定（不写死名单）。

## 面板那一行是怎么排的

`hint`/`detail` 的宽度预算只有一行：**只写结论 + 一个动作**。
例：「未装官方 CLI「qianwen」· 登录：`qianwen auth login`」。
「为什么取不到」的论证（路径清单、404 计数、签名要求）属于本页，不属于面板 —— 那几行被截断过
（实测横向溢出 68px / 11px），收文案的同时把依据搬到这里，才不会再被下一条细节挤破。
